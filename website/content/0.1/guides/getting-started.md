## Create a project

Use the [project generator](/generate), or create a Gradle project with the
Fenix plugin:

```kotlin title="build.gradle.kts"
plugins { id("fr.d4emon.fenix.dev") version "0.1.5" }

group = "com.example"
version = "1.0.0"

fenix { minecraft = "26.2" }
```

Run `./gradlew runClient`. The plugin downloads the matching game, compiles the
mod and launches it. Fenix supports Minecraft 26.2 and newer releases only; it
is never backported to an older Minecraft version.

## Add the mod entry point

Every mod has one class annotated with `@Mod`. It is the only Java class the
minimal generated project contains.

```java title="src/main/java/com/example/mymod/MyMod.java"
package com.example.mymod;

import fr.d4emon.fenix.api.Fenix;
import fr.d4emon.fenix.api.FenixMod;
import fr.d4emon.fenix.api.Mod;

@Mod("my-mod")
public final class MyMod implements FenixMod {
    @Override
    public void onInit(Fenix fenix) {
        fenix.logger().info("My Mod is ready");
    }
}
```

`FenixMod` has three useful phases:

| Method | Use it for |
|---|---|
| `onPreLaunch` | transforms and payload types that must exist before game classes load |
| `onRegister` | blocks, items and other registry entries |
| `onInit` | events, config and normal mod setup |

## Your classes are your classes

`ModContent` is **not** a class provided by Fenix API. It is only a common name
for a class written by a mod author. You can call yours `Content`, `MyItems` or
split it into any structure that makes sense for your mod.

The API class is `Registrar`. Your code owns the fields; `Registrar` owns the
safe interaction with Minecraft's registries:

```java title="src/main/java/com/example/mymod/Content.java"
package com.example.mymod;

import fr.d4emon.fenix.registry.Holder;
import fr.d4emon.fenix.registry.Registrar;
import net.minecraft.world.item.Item;

public final class Content {
    public static final Registrar REGISTRAR = Registrar.of("my-mod");
    public static final Holder<Item> COPPER_TOKEN = REGISTRAR.item("copper_token");

    private Content() {
    }
}
```

Then apply registrations in your entry point:

```java
@Override
public void onRegister(Fenix fenix) {
    Content.REGISTRAR.apply();
}
```

Nothing above is generated by the project generator. It is an example of how a
mod may organise content once it actually needs an item. See [Content and
registries](/docs/@latest/guides/content) for blocks, creative tabs and the role
of `Holder`.
